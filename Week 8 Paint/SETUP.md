# Week 8 — Configuration Interface (multi-participant paint by numbers)

Bare-minimum build that still hits every rubric row. Order matters — do not skip ahead.

## 0. Project

1. `C:\Code\VR\VR Template` → copy → rename to `Week 8 Paint`.
2. Unity Hub → Add project from disk → `Week 8 Paint`. First open rebuilds `Library/`, give it a few minutes.
3. Open `Assets/Scenes/BaseScene.unity`. XR rig, teleport and grabbing are already in it (activities a + b are done).

## 1. Photon Fusion (activity c)

1. Window → Package Management → Asset Store → search **Photon Fusion — Multiplayer SDK** (free) → Add to My Assets → Import into the project.
2. Fusion Hub opens. Go to the Photon dashboard, create a **Fusion 2** app, copy the App ID, paste it into the **App Id** field in the Hub.
3. In the Hierarchy: right click → **Fusion → Scene → Setup Networking in the Scene**. You get **Prototype Runner** and **Prototype Network Start**.
4. On Prototype Network Start, set it to **auto start in Shared mode**.
5. Press play — the console should report a connected session before you go any further.

## 2. Avatar (activity d)

1. Empty object `Avatar`:
   - Cylinder body — posY `0.3`, scale `0.3`
   - Cube nose — pos `(0, 0.3, 0.15)`, scale `0.05`
2. On the root: **Network Object**, **Network Transform**, **MoveAvatar**.
3. Drag it into `Assets/Prefabs` to make it a prefab, then delete it from the scene.
4. Add **JoinPlayer** to the **Prototype Runner** object, and drag the Avatar prefab into its `Avatar Prefab` field.

Test with two clients before continuing (see section 6).

## 3. Picture (activity e)

1. Cube named `Picture` — scale `(1.5, 1.5, 0.05)`, stood up in front of the rig.
2. Remove the Box Collider, add a **Mesh Collider**. `PaintBrush` reads `hit.textureCoord`, which only works on a mesh collider.
3. Add **Network Object** and **PaintCanvas**.
4. Give it a new material (URP/Lit). `PaintCanvas` overwrites its texture at runtime.
5. Hierarchy → right click → **Fusion → Scene → Bake Scene Objects**. Scene objects with a Network Object need baking or their RPCs will not fire.

The picture is generated in code as three concentric rings, which is the "count the colours" part — `RegionCount` is 3, and the console logs it on spawn.

## 4. Brush (activity f + g)

1. Empty object `Brush`:
   - Cylinder handle — scale `(0.03, 0.1, 0.03)`
   - Cube head at the top — scale `0.05`
   - Empty `Tip` just past the head, **rotated so its blue Z axis points out of the brush**
2. On the root: Rigidbody (gravity off is easiest), a collider, **XR Grab Interactable**, **PaintBrush**.
3. In PaintBrush: `Brush Tip` = the Tip object, `Brush Head Renderer` = the cube head.
4. Leave it on a table in front of the rig so it can be grabbed.

## 5. Colour selector (the actual challenge — configuration interface)

1. Three or four small cubes in a row beside the picture.
2. On each: a collider, **XR Simple Interactable**, **ColourSwatch**.
3. Set `Colour` per swatch (red, green, blue, yellow) and drag the scene's `Brush` into the `Brush` field on each.
4. Each swatch tints itself to its own colour at runtime, so no labels are needed.

## 6. Test (activity i)

1. File → Build and Run to produce a second client.
2. Editor + built app both connect to the same shared session.
3. Check: two avatars, each moves with its own headset; pick a colour, touch the picture with the brush; **the same ring changes colour in both windows**.

That last check is the one being marked — it proves the RPC in `PaintCanvas` is replicating.

## Talking points if the tutor asks

- **Why regions instead of pixels** — the picture is stored as a region index per pixel plus one colour per region, so a paint stroke sends an `int` and a `Color` over the network instead of an image, and every client rebuilds the same texture from the same data.
- **Why `Spawned()` not `Start()`** — Fusion has not finished networking the object during `Start`, so `HasInputAuthority` and RPCs are not valid yet.
- **Why `RpcTargets.All` and not just the others** — the painter repaints through the same call as everyone else, so there is one code path and no chance of the local copy drifting from the replicated one.
- **Why the authority check in `MoveAvatar`** — every client runs the script on every avatar; without it, each client would drag all avatars around with its own headset.
- **Extending it** — region count, texture size and the swatch colours are all serialized fields, and the pattern is generated by one method, so swapping the rings for a different picture is a change in `BuildRegions()` alone.
